# API Contracts: Authentication Endpoints

**Feature**: SSO-Only Authentication | **Date**: 2026-08-18

## Overview

The authentication API provides endpoints for initiating OAuth2 login, handling callbacks, logging out, and retrieving user profile information. All endpoints follow REST conventions and return JSON responses. Authentication state is managed via HTTP-only secure session cookies.

---

## Endpoints

### 1. Login Initiation

**Endpoint**: `GET /api/auth/login`

**Purpose**: Initiate Google OAuth2 authorization code flow. Redirects user to Google's consent screen.

**Request**:
```
GET /api/auth/login HTTP/1.1
Host: localhost:8080
```

**Query Parameters** (optional):
- `redirectUri` (string, optional): Where to redirect after successful login. If not provided, defaults to application homepage.

**Response** (on success):
```
HTTP/1.1 302 Found
Location: https://accounts.google.com/o/oauth2/v2/auth?client_id=...&scope=openid+email+profile&state=...
```

**Response** (on error):
```
HTTP/1.1 400 Bad Request
Content-Type: application/json

{
  "timestamp": "2026-08-18T10:30:00Z",
  "status": 400,
  "error": "InvalidOAuth2Request",
  "message": "OAuth2 configuration is missing or invalid",
  "path": "/api/auth/login"
}
```

**Security**:
- Anonymous access allowed (unauthenticated users can initiate login)
- CSRF protection enabled
- Redirect URI must match configured allowed origins (Spring Security CORS config)

**Notes**:
- Actual OAuth2 authorization endpoint is handled by Spring Security's `spring-security-oauth2-client`
- This endpoint is called by frontend via `window.location` or redirect link in `auth.service.ts`
- `state` parameter generated by Spring Security to prevent CSRF attacks
- Route defined in `SecurityConfig.java` in `config/` package

---

### 2. OAuth2 Callback (Internal)

**Endpoint**: `GET /login/oauth2/code/google`

**Purpose**: OAuth2 callback endpoint. Handles authorization code exchange, token retrieval, and user provisioning. **This endpoint is handled internally by Spring Security; not directly called by frontend.**

**Request**:
```
GET /login/oauth2/code/google?code=<auth_code>&state=<state> HTTP/1.1
Host: localhost:8080
```

**Query Parameters**:
- `code` (string, required): Authorization code from Google
- `state` (string, required): CSRF state token
- `error` (string, conditional): Error code if user denied consent (e.g., `access_denied`)

**Response** (on success):
```
HTTP/1.1 302 Found
Location: http://localhost:4200/home
Set-Cookie: SESSION=<session_id>; Path=/; Secure; HttpOnly; SameSite=Strict; Max-Age=43200
```

**Response** (on error):
```
HTTP/1.1 302 Found
Location: http://localhost:4200/login?error=oauth2_failure&message=<URL-encoded message>
```

**Side Effects** (on success):
- Exchanges authorization code for access/ID tokens with Google
- Calls Google's userinfo endpoint to retrieve user profile (email, name, picture)
- Checks UserRepository for existing user by (provider="Google", provider_user_id=<Google subject>)
- If not found, creates new User entity with profile data
- Establishes Spring Session, stores session ID in HTTP-only cookie
- Redirects to homepage

**Security**:
- State parameter validated to prevent CSRF
- Authorization code exchange happens server-side (never exposed to frontend)
- Session cookie is HTTP-only, Secure, SameSite=Strict
- HTTPS required in production

### 3. Logout

**Endpoint**: `POST /api/auth/logout`

**Purpose**: Terminate user session and clear authentication state.

**Request**:
```
POST /api/auth/logout HTTP/1.1
Host: localhost:8080
Content-Type: application/json
Cookie: SESSION=<session_id>
```

**Request Body**: (empty)

**Response** (on success):
```
HTTP/1.1 200 OK
Content-Type: application/json
Set-Cookie: SESSION=null; Path=/; Secure; HttpOnly; SameSite=Strict; Max-Age=0

{
  "status": "logged_out",
  "message": "Session terminated successfully"
}
```

**Response** (when not authenticated):
```
HTTP/1.1 401 Unauthorized
Content-Type: application/json

{
  "timestamp": "2026-08-18T10:30:00Z",
  "status": 401,
  "error": "Unauthorized",
  "message": "No active session found",
  "path": "/api/auth/logout"
}
```

**Side Effects** (on success):
- Invalidates session in Spring Session store
- Clears HTTP-only session cookie (expires immediately)
- Subsequent requests without session cookie treated as unauthenticated

**Security**:
- Requires authenticated user (Spring Security @PreAuthorize("isAuthenticated()"))
- CSRF protection enabled

**Idempotency**: Can be called multiple times; subsequent calls after first logout return 401.

---

### 4. Get User Profile

**Endpoint**: `GET /api/auth/user/profile`

**Purpose**: Retrieve authenticated user's persisted profile information from the User entity.

**Request**:
```
GET /api/auth/user/profile HTTP/1.1
Host: localhost:8080
Cookie: SESSION=<session_id>
```

**Response** (on success):
```
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 42,
  "provider": "Google",
  "email": "user@example.com",
  "displayName": "John Doe",
  "avatarUrl": "https://lh3.googleusercontent.com/a/ABC..."
}
```

**Response** (when not authenticated):
```
HTTP/1.1 401 Unauthorized
Content-Type: application/json

{
  "timestamp": "2026-08-18T10:30:00Z",
  "status": 401,
  "error": "Unauthorized",
  "message": "No active session found. Please login.",
  "path": "/api/auth/user/profile"
}
```

**Response** (partial data — optional fields missing):
```
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 43,
  "provider": "Google",
  "email": null,
  "displayName": "Jane",
  "avatarUrl": null
}
```

**Notes**:
- Returns data from User entity persisted in database (not from current OAuth token)
- Optional fields (email, displayName, avatarUrl) may be null if provider didn't return them on sign-in
- `id` is database-generated primary key (not OAuth provider ID)
- Response time target: <200ms (measured from request arrival to response sent)

**Security**:
- Requires authenticated user (Spring Security @PreAuthorize("isAuthenticated()"))
- Returns only current user's profile (no user ID parameter; uses authenticated principal)

## Error Response Format

All error responses follow a consistent format:

```json
{
  "timestamp": "2026-08-18T10:30:00Z",  // UTC timestamp when error occurred
  "status": 400,                        // HTTP status code
  "error": "ErrorType",                 // Machine-readable error type
  "message": "User-friendly message",   // Readable error description
  "path": "/api/auth/endpoint"          // Request path that caused error
}
```

### Common Error Types & Status Codes

| Status | Error Type | Cause | Example Message |
|--------|-----------|-------|---------|
| 400 | BadRequest | Malformed request, missing required field | "Authorization code is missing" |
| 400 | InvalidOAuth2Request | OAuth2 config missing or invalid | "OAuth2 client credentials not configured" |
| 401 | Unauthorized | No active session, expired token | "No active session found. Please login." |
| 403 | Forbidden | Access not allowed (not used in auth endpoints) | — |
| 500 | OAuth2AuthenticationException | Google API unreachable, token exchange failed | "Failed to exchange authorization code. Please try again." |
| 500 | InternalServerError | Database error, unexpected exception | "An unexpected error occurred. Please try again later." |

## Session Management

### Session Cookie

The session cookie is set by Spring Security on successful authentication:

```
Set-Cookie: SESSION=<session_id>; Path=/; Secure; HttpOnly; SameSite=Strict; Max-Age=43200
```

**Attributes**:
- **SESSION**: Spring's default session cookie name
- **<session_id>**: Opaque identifier managed by Spring Session
- **Path=/**: Cookie sent with all requests
- **Secure**: Cookie only sent over HTTPS (production)
- **HttpOnly**: Prevent JavaScript access (XSS protection)
- **SameSite=Strict**: Prevent CSRF attacks (cookie not sent on cross-site requests)
- **Max-Age=43200**: 12 hours (43200 seconds)

**Refresh**: Session expiry is absolute (12 hours from creation). Activity does NOT extend the session.

### Authentication Flow in Frontend

Frontend doesn't need to manage tokens explicitly. Spring Security handles:

1. **Login**: Call `GET /api/auth/login` or navigate to `/oauth2/authorization/google`
2. **Callback**: Google redirects to `/login/oauth2/code/google` (handled by browser automatically)
3. **Session Established**: Browser receives SESSION cookie, automatically included in subsequent requests
4. **Protected Endpoints**: Call endpoints with standard HTTP requests; browser includes cookie
5. **Logout**: Call `POST /api/auth/logout`; browser clears cookie

### CORS & Cookie Credentials

**Important for SPA frontend**:

If frontend is on different domain/port (e.g., `localhost:4200` while backend is `localhost:8080`):
- Frontend must include `withCredentials: true` in HTTP client configuration
- Backend must explicitly allow credentials via CORS headers: `Access-Control-Allow-Credentials: true`

**Angular HTTP Client Setup**:
```typescript
this.httpClient.get('/api/auth/user/profile', {
  withCredentials: true  // Include cookies in cross-origin requests
})
```

## Testing Scenarios

### Scenario 1: First-Time Login Flow

```
1. GET /api/auth/login
   → 302 Redirect to Google consent screen
   
2. [User completes Google OAuth at Google.com]

3. GET /login/oauth2/code/google?code=<code>&state=<state>
   → Backend exchanges code for token
   → Backend fetches user profile from Google
   → Backend creates User entity in database
   → Backend sets SESSION cookie
   → 302 Redirect to homepage
   
4. GET /api/auth/user/profile (with SESSION cookie)
   → 200 OK with user profile
```

### Scenario 2: Session Expiry

```
1. GET /api/auth/user/profile (with valid SESSION cookie)
   → 200 OK
   
2. [Wait 12 hours or modify session cookie expiry to past time]

3. GET /api/auth/user/profile (with expired SESSION cookie)
   → Spring Session invalidates cookie
   → 401 Unauthorized
   
4. Frontend redirects to /api/auth/login
```

### Scenario 3: Logout

```
1. GET /api/auth/user/profile (authenticated)
   → 200 OK
   
2. POST /api/auth/logout
   → 200 OK
   → Set-Cookie: SESSION=null; Max-Age=0 (clears cookie)
   
3. GET /api/auth/user/profile (no SESSION cookie)
   → 401 Unauthorized
```

## Rate Limiting & Throttling

Not in scope for this feature (pet project). If needed in future:
- Consider Spring Cloud Gateway or custom HandlerInterceptor
- Recommended: 10 login attempts per IP per minute (prevent brute force)
- Profile endpoint: No explicit limit (relies on Spring Session thread pool)
