## Summary

The Inventory Categories feature enables users to create, rename, and delete named groups (categories) for organizing inventory items. The system enforces category name uniqueness per user (case-insensitive, whitespace-trimmed) and prevents deletion of categories with assigned items, requiring explicit manual item reassignment first. Concurrent edits from multiple sessions are detected and handled with clear error messages and automatic list refresh. The feature leverages the existing multi-user authentication and Spring Data persistence layer to maintain data integrity and user isolation.

## Technical Context

**Language/Version**: Java 17+, Spring Boot 3.x

**Primary Dependencies**: Spring Boot Web, Spring Data JPA, PostgreSQL Driver, Flyway (database migrations)

**Scale/Scope**: Per-user category management (typical users manage 10-100 categories); integrated with existing inventory items feature

## Key Design Decisions

### 1. Database Schema

- **Category Table**: Single table with fields: `id` (PK, UUID), `userId` (FK to user), `name` (VARCHAR, unique per user), `createdAt` (TIMESTAMP), `updatedAt` (TIMESTAMP), `version` (for optimistic locking)
- **Uniqueness Constraint**: Composite unique index on `(userId, LOWER(TRIM(name)))` to enforce case-insensitive, per-user uniqueness after trimming
- **Whitespace Handling**: Name trimmed by application layer before storage; database trigger or constraint validates non-empty after trim
- **Item Relationship**: Inventory items table has optional `categoryId` (FK to category, nullable) — deletion blocked if any items reference the category

### 2. Validation Strategy

- **Request DTO Validation**: Jakarta Validation annotations (`@NotBlank`, `@Size`, etc.) on CreateCategoryRequestDTO and RenameCategoryRequestDTO
- **Service Layer Validation**: Business rule checks (uniqueness, user isolation, deletion guards) in CategoryService
- **Database Constraints**: Unique indexes, foreign keys, NOT NULL constraints replicate application rules at persistence layer for data integrity

### 3. Concurrent Edit Handling

- **Optimistic Locking**: Use JPA `@Version` annotation on Category entity for version-based conflict detection
- **On Conflict**: Service detects version mismatch, throws `OptimisticLockException`; centralized advice translates to HTTP 409 (Conflict) response
- **Frontend Recovery**: On HTTP 409, frontend shows error message ("Category no longer exists" or "Name already taken") and automatically refreshes category list

### 4. Exception Hierarchy & Error Handling

- **Custom Exceptions** (service layer throws these):
  - `CategoryNameNotUniqueException` → HTTP 400 Bad Request ("Category name already exists")
  - `CategoryHasItemsException` → HTTP 409 Conflict ("Cannot delete: X items assigned")
  - `CategoryNotFoundException` → HTTP 404 Not Found
  - `UnauthorizedException` → HTTP 403 Forbidden (category belongs to another user)
- **Centralized Mapping**: Spring `@ControllerAdvice` (GlobalExceptionHandler) maps domain exceptions to consistent error DTOs with appropriate HTTP status codes
- Controllers pass exceptions through; no try/catch logic in controller methods

### 5. User Data Isolation

- **Service Layer**: All repository queries filter by authenticated user ID; no raw queries without user context
- **Repository Methods**: Follow pattern `findByUserIdAndId()`, `findAllByUserId()`, `deleteByUserIdAndId()`
- **Security**: Spring Security integration ensures authenticated user ID is available to service layer
- No user can list, view, modify, or delete categories owned by other users

## Testing Strategy

### Unit Tests (Service & Controller)

- **Service Layer Tests** (CategoryServiceTest.java):
  - `testCreateCategorySuccess()` — Valid input creates and returns category
  - `testCreateCategoryNameAlreadyExists()` — Duplicate name rejected with exception
  - `testRenameCategorySuccess()` — Category renamed, items remain associated
  - `testRenameCategoryToExistingName()` — Rename to duplicate name rejected
  - `testDeleteCategorySuccess()` — Empty category deleted
  - `testDeleteCategoryWithItemsBlocked()` — Deletion blocked, exception thrown with item count
  - `testUserIsolationEnforced()` — User cannot access/modify other users' categories
  - `testNameTrimming()` — Whitespace trimmed, case-insensitive uniqueness enforced

- **Controller Layer Tests** (CategoryControllerTest.java):
  - `testCreateCategoryEndpoint200()` — Valid POST returns 201 Created
  - `testCreateCategoryEndpoint400OnDuplicate()` — Duplicate name returns 400 Bad Request
  - `testDeleteCategoryEndpoint409WhenItemsAssigned()` — Delete with items returns 409 Conflict
  - `testGetCategoryListAuthenticatedUser()` — User sees only their categories

### Integration Tests (End-to-End)

- **CategoryIntegrationTest.java** (H2 in-memory database):
  - Full category lifecycle: create → verify in list → rename → verify rename → delete empty → verify deletion
  - User isolation: two users create same-named categories independently
  - Concurrent edits: simulate version conflict, verify 409 response and auto-refresh signal
