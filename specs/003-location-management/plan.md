# Implementation Plan: Location Management

**Branch**: `003-location-management` | **Date**: 2026-08-19 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/003-location-management/spec.md`

## Summary

Enable users to organize their inventory by creating, renaming, and deleting storage locations with per-user unique names. Implement using Spring Boot layered architecture (controller → service → repository) with centralized exception handling, persistent storage in PostgreSQL via Spring Data, and comprehensive logging for audit trails.

## Technical Context

**Language/Version**: Java 17+ with Spring Boot 3.x

**Primary Dependencies**: Spring Boot, Spring Data JPA, Spring Security (OAuth2), Flyway, PostgreSQL driver, SLF4J/Logback

**Storage**: PostgreSQL relational database with versioned schema migrations via Flyway

**Testing**: JUnit 5, Mockito, Spring Test framework

**Target Platform**: Linux/macOS server; deployed as a Java web application

**Project Type**: Web service (Spring Boot REST API backend + Angular frontend)

**Performance Goals**: Location operations complete within 1 second (from spec success criteria); 95% success rate under normal load

**Constraints**: Per-user location name uniqueness enforced at application level and database level; user data isolation required

**Scale/Scope**: Personal/small-business inventory management; assume <1000 locations per user, <100k total users in v1

### UI/UX Behavior

#### Create Location Flow
1. User clicks "Create Location" button
2. LocationFormComponent opens in modal/dialog
3. User enters location name (e.g., "Home Office")
4. User clicks "Create"
5. LocationService calls POST /locations API
6. On success: Modal closes, list refreshes, location appears
7. On error: Error message displayed in form (e.g., "Name already exists")

#### Rename Location Flow
1. User clicks "Rename" icon next to location
2. LocationFormComponent opens pre-filled with current name
3. User edits name (e.g., "Home Office" → "Home Office 2")
4. User clicks "Update"
5. LocationService calls PUT /locations/{id} API
6. On success: Modal closes, list updates with new name
7. On error: Error message displayed in form

#### Delete Location Flow
1. User clicks "Delete" icon next to location
2. Confirmation dialog appears: "Are you sure you want to delete '{name}'?"
3. If confirmed:
   - LocationService calls DELETE /locations/{id}
   - On success: Location removed from list
   - On error: Error message appears (e.g., "Cannot delete location with items. Please remove or reassign items first. (itemCount: 2)")
4. If canceled: Dialog closes, no action taken

#### Error Handling
- **409 LOCATION_NAME_NOT_UNIQUE**: "A location with this name already exists. Please choose a different name."
- **404 LOCATION_NOT_FOUND**: "Location not found. It may have been deleted."
- **409 LOCATION_HAS_ITEMS**: "Cannot delete location with items. Please remove or reassign items first. (itemCount: X)"
- **Network error**: "Unable to connect. Please check your connection and try again."
